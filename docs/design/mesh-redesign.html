gst 分层 mesh 设计

把 mesh 收敛成三层，每层只做一件事。机器加入后一直是成员，离线只是状态，只有 gst remove 让它离开。完整的规格在 mesh.md，这一页用图讲同一个方案（实现与评审稿不同的几处列在 mesh-redesign.md 开头）；协议 5 的做法见 control-plane.html。

① 链路层

一条 SSH 连接就是一根帧管道

握手一次，之后双方随时发帧。不再有 yamux，不再有流。只知道管道另一头是谁。

② 状态层

一张每台机器都相同的表

成员、链路、移除记录、subnet 都是表里的条目。靠洪泛传遍全网，写在磁盘上，不过期。

③ 路由层

给任何一台机器发一条消息

消息带着目的地，每台机器按自己的路由表转给下一跳。请求、应答、WireGuard 包都是消息。

02

① 链路层：握手一次，之后只有帧

发起方的 daemon 用 SSH 连到对端，执行 gst peer-bridge，它把标准输入输出接到对端 daemon 的 control socket。这一步和现在一样。变的是之后在这条连接上说什么。

握手：每方一个 Hello

SSH 连接接通之后，两个 daemon 还互不认识。握手就是双方各发一个 Hello、各自检查对方的这一步。通过之前这条连接什么都不运，通过之后才算一条链路。

① {"protocol": 6, "software": "gst 0.7.0", "role": "peer",
   "node": {"id": "3f9c…", "name": "laptop"},
   "member": {"generation": 0,
              "admit": true}}   // 只在 gst add 之后、第一次握手成功之前

② {"protocol": 6, "software": "gst 0.7.0", "role": "peer",
   "node": {"id": "8b21…", "name": "devbox"},
   "member": {"generation": 0}}
Hello 回答的问题字段谁来判断
说的是同一种话吗protocol、software、role① 链路 版本不同就拒绝，并告诉用户两边各是什么版本
你是谁node① 链路 连到自己就拒绝；之后按这个 id 向上报告
你还是这个网络的吗member应用 链路层不看里面，只负责传和转达结论
  • protocol 是整个 gst 协议的版本，不属于哪一层：帧格式、消息头、条目格式、方法，任何一处变了都加 1。握手是两台机器第一次接触的地方，所以在这里检查。
  • role 说明这条连接是干什么的。daemon 的 control socket 有两种来客：本机的 gst 命令是 control，另一台机器的 daemon 是 peer。只有 peer 是链路。
  • 拒绝。接受方不通过时，② 换成带 error 的 Hello；发起方不通过时发一个 bye 帧。因为被移除而拒绝时附上移除记录。两种情况都随即关闭连接。

一条连接的三个状态，只往前走

握手中只收发 Hello。上面的层还看不到这条链路。
→
运行只收发帧。向状态层和路由层报告 Up。
→
结束连接关闭，报告 Down。重连是一条新连接，重新握手。

帧

lengthuint32
type1 字节
body最多 1 MiB
type归谁body队列
sync② 状态JSON：一批条目优先
msg③ 路由38 字节的头 + 载荷。请求、应答、包都是它请求和应答优先；包不优先
alive① 链路空。15 秒没发过任何帧就发一个优先
bye① 链路JSON：结束的原因，被移除时附上移除记录优先
  • 链路层不拆 body。它只按 type 把帧交给上面的一层。请求和应答怎么区分，是路由层看消息头里的 kind。进哪个队列由发送的一方说：Send(type, body, urgent)。
  • 两个发送队列。优先队列总是先发；包的队列满 1024 个就丢。大量流量不会拖住同步和调用。
  • 保活只有一种。45 秒没收到任何帧，链路结束。SSH 客户端的 keepalive 和 yamux 的 keepalive 都去掉：alive 走完 daemon 到 daemon 的整条路，SSH keepalive 只到对端的 sshd，而且接受方的 daemon 根本看不到它。
  • 重连。发起方等 5 秒起、翻倍、最长 5 分钟；本机换了网络时清零，立即重连。

② 状态层：一张表，三种条目

表是一组互相独立的条目，每条是 {key, version, value}。合并、同步都一条一条做：收到一条，按它的类型比较 version，大的留下。下面是一个三台机器的网络里，每台机器最终都持有的表，tablet 被移除过。

keyversionvalue
node/laptop[0, 1793…000]name、software、links: [devbox]、net: {address: 10.99.3.7, public_key}
node/devbox[0, 1793…123]links: [laptop, gateway]，address: 10.99.8.2 …
node/gateway[0, 1793…456]links: [devbox]，address: 10.99.1.9 …
node/tablet[0, 1793…789]已删除：它的代数 0 不大于下面那条移除记录的 0
removed/tablet[0]by: devbox，at: 2026-11-10T08:00Z
network[0, −1793…000]subnet: 10.99.0.0/16，auto: true

key 里实际是 id，这里写成名字。gst IP 不是单独的条目，就是 node 条目里的 net.address。表写在磁盘上，重启后还在。

node/<id>

只有这台机器自己写

版本 [generation, seq]。seq 每次内容变化就加大，新的盖掉旧的。

离线的机器，条目原样留着：它仍是成员。seq 跟随时钟，也就是它最后一次发布的时间，在线时每 10 分钟重新发布。

removed/<id>

任何机器都能写：gst remove

版本 [generation]：移除的是哪一代。node 的代数不大于它，就不是成员。

永久保存，每条几十字节。

network

任何机器都能写：gst subnet

版本 [manual, order]：人选的胜过自动选的；人选的之间后选的胜；自动选的之间先选的胜。

取代每台机器各自上报的 net.since。

为什么版本里有两个数

seq 回答"同一台机器的哪条内容更新"，generation 回答"这是它第几次加入网络"。tablet 的一生：

node [0, 5]node [0, 9]→removed [0]→node [0, 12]被拒→ gst add →node [1, 1]

只有 seq 的话，被移除的 tablet 如果还没收到消息，继续发布 seq 更大的条目，就把自己带回网络了。代数只在有人执行 gst add 时才加 1，它自己改不了，所以移除压得住这一代的所有条目。

同步就是洪泛，两条规则

  1. 链路一建立，双方把整张表发给对方：sync {"entries": […]}。
  2. 收到一条条目，和手里的比。更新：替换，写盘，发给除了来源以外的每个邻居。不更新：丢弃，到此为止。

每条链路不用记任何东西：没有摘要，不记对方有什么，也不记自己发过什么。一条条目在每台机器上只有第一次到达时算新，所以传播会停。每个 key 只留最新的一条。

没有东西会过期：断开多久，重连时再互发一次整张表就补齐。20 台机器的表约 10 KB。

③ 路由层：消息自己带着目的地

现在调用远处的机器，要先用 relay.open 逐跳打通一个流，再在流上调用；运包另有一套长期的流。新设计里只有一样东西：消息。

to16 字节 id
from16 字节 id
ttl1
kind1
iduint32
payload请求 / 应答是 JSON，包是密文
kindpayload走哪
1 请求{"method", "params"}SSH 链路，逐跳
2 应答{"result"} 或 {"error"}，id 和请求相同SSH 链路，逐跳
3 包WireGuard 密文本机发出、且有 UDP 路径时走 UDP；否则 SSH 链路

每台机器对每条消息做同样的事

  1. to 是自己：交给本机。请求进方法分发，应答交给等着的调用，包交给 WireGuard。
  2. 否则 ttl 减 1，查自己的路由表，发给下一跳。ttl 到 0 就丢。
  3. 没有下一跳：包丢掉；请求则由这台机器回一个 unreachable，调用方马上失败，不用等超时。

路由表每台机器自己算：状态表里两端都列出对方的链路构成图，从本机做广度优先搜索。状态表一变就重算。链路断了，下一条消息就走新的路，没有流要重建。

远程方法剩 6 个：ping、status、net.networks、direct.offer、direct.update、direct.trace。都是一个请求、一个应答，都幂等，不自动重试。

UDP 路径是捷径，不是链路

  • 它只运两台机器自己之间的 WireGuard 包，不带帧也不带消息头。
  • 中间的机器不用 UDP 替别人转发：收的一方会把包算作 UDP 对端发来的，回包就发错了地方。
  • 打洞是应用层的事：本机有包要发给某台机器、又没有 UDP 路径时，用一个普通的 direct.offer 请求交换地址，然后双方互相探测。沿途的机器只是照常转发这个请求。

成员：加入、离线、移除

是什么表现
成员表里有它的 node 条目，且没有压过它的移除记录有名字、有 gst IP、WireGuard 认识它
在线本机现在有到它的路由或 UDP 路径direct / relay
离线是成员，但现在到不了offline 和最后在线时间（取自它条目版本里的 seq）；名字照样解析，地址照样占着；一回来就能用
被移除有移除记录压着它这一代各机器删掉指向它的 link，拒绝它的连接

命令

命令做什么
gst add <destination>本机建一条到它的 link。它还不是成员就加入；已是成员就多一条 link；本机已有到它的 link 就替换。-- 之后是 ssh 参数。
gst remove <machine>在任意一台机器上执行。写一条移除记录，全网收敛。移除本机就是离开网络。
link、--remote-gst删除；unlink 只删本机的一条 link。

不同时在线也会收敛

情况结果
移除时某台机器离线它连上任何知情的机器，对方发来的表里就有移除记录
被移除的机器离线，回来后用旧 link 连回来握手被拒，拒绝里带着移除记录，它于是知道
两台都不知情的机器先连上了暂时是个小岛；任一方连上知情的机器后收敛
离线期间它被移除又被加回来别人手里是旧代数，互发表之后收敛到新的
两台机器同时移除它两条记录相同
网络分开时一边移除了它合并后移除记录胜

事情现在新设计

08

已经定下的

  • 移除自己等于离开网络，效果和被别人移除相同。
  • 路由按跳数选最短。
  • 最后在线时间就是 node 条目的 seq（Unix 纳秒），全网复制。
  • 对端 gst 的位置固定为 $HOME/.local/state/gst/bin/gst，gst up 时链接过去。
  • 表的上限：node 和 removed 各 1024 条，单条 64 KiB。
