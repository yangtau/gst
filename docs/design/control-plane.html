GST · DESIGN NOTES

gst 控制面现状

机器之间的控制信息怎么走，每一类状态由谁写、怎么传、冲突时听谁的，以及哪些地方现在没有一致性保证。本文描述的是协议 5 的做法，已被协议 6 的分层设计取代（见 mesh-redesign.html 和 mesh.md），保留用来对照。

控制信息走哪

只走 SSH link

记录、信令、查询都在 link 的 yamux 流上。UDP 路径只运 WireGuard 包和自己的 probe / answer / bye，不运任何控制状态。

怎么到达远处的机器

两种走法

全网状态用洪泛：逐跳转发给相邻机器。对某台机器的调用用源路由：发起方按自己的视图算好路径，relay.open 沿 link 逐跳打通一个流。

一致性

只有记录最终一致

每台机器只写自己的记录，按 seq 新者胜；同一连通分量内最终一致。其余都是尽力而为：调用不重试，记录 30 分钟过期，重启后从零同步。

01

一条 link 上跑什么

link 是一台机器的 daemon 主动建立的 SSH 连接。连接里执行 gst peer-bridge，它把标准输入输出接到对端 daemon 的 control socket。之后两个 daemon 直接对话：

SSH 连接
由发起方的 daemon 建立：ssh -G 解析目标，只信 known_hosts，每 15 秒 keepalive（默认，3 次不回即断）。
exec peer-bridge
对端执行 gst peer-bridge，接到对端 daemon；对端没 gst up 时拒绝。
Hello（peer）
双方交换协议版本、software、yamux feature；30 秒内完成，版本不同即拒绝。
yamux 会话
之后两个方向对等：谁发起 link 不再重要，双方都能开流，一个流承载一次调用；yamux 自己每 15 秒 keepalive。
流
node.info、topology.sync（长期开着）、relay.open（中转）、direct.offer 等，见下表。

任何一层断了，整条 link 就结束：所有流一起断，两端各自删掉这条边、重新发布记录；发起方按退避重连（5 秒起，每次翻倍，最长 5 分钟，连上后重置）。

所有 peer 方法和它们的走法

方法走法什么时候内容失败时
node.info相邻 / 源路由link 建好时双方各一次；gst pingid、名字、software建 link 时失败则断开 link
topology.sync洪泛link 建好时双方各开一个，一直开着先回比对方 known 新的记录，之后每次变化推一帧流出错就关闭整条 link，重连后从 known 重新对齐
relay.open源路由调用不相邻的机器时path：剩下要经过的节点 id某一跳没有到下一跳的 link 就原路返回错误，不换路
node.status源路由gst status <machine>对方 daemon 的完整 Status报错给用户
net.networks源路由网络里还没有 subnet，第一次自动选时对方网卡和路由的网段3 秒没回就当它不存在
net.packets源路由有包要发、又没有 UDP 路径时之后这个流双向运 WireGuard 包路径断了流就断，1 秒后按新视图重开；排队的包丢弃
direct.offer源路由包走 link 时，每 5 秒最多一次token、候选 IP:port退避 5 秒起翻倍，最长 5 分钟
direct.update源路由本机地址或网卡变了运行中路径的 token 和新地址不重试；路径自己会重新探测
direct.trace源路由gst ping -v对方最近一次打洞的过程显示取不到的原因
link.remove相邻gst unlink 停掉 link 之前调用方 id、link id3 秒没送到就算了
probe / answer / byeUDPUDP 路径的探测和维持token、时间、看到的来源地址不是控制状态：只用来找路和保活

相邻 只在一条 link 的两端之间；洪泛 逐跳转发直到全网都有；源路由 发起方用自己的视图选好整条路径，沿途每台机器只看 path[0] 是不是自己、有没有到 path[1] 的 link。

03

唯一复制到全网的状态：记录

{
  "node":    {"id": "…", "name": "laptop", "software": "gst 0.6.0"},
  "seq":     1793700000000000000,     // max(上次+1, 见过的自己最大 seq+1, 当前 Unix 纳秒)
  "expires": "…30 分钟后…",           // 每 10 分钟刷新；每分钟清一次过期的
  "links":   [{"link": "2e340426d1c2", "peer": "…devbox 的 id…"}],
  "net":     {"subnet": "10.99.0.0/16", "since": …, "address": "10.99.3.7", "public_key": "…"}
}
  • 单一写者：每台机器只发布自己的记录。别人的记录只会原样转发，不会被修改。
  • 新者胜：收到 seq 更大的才替换。替换了就唤醒本机所有 topology.sync 流，把它推给对端还没收到的。
  • 每个流记着自己推过什么（sent），但不记得对端从别处已经收到什么，所以新记录会在每条 link 上反向回推一次，对端因为不比手里的新而丢弃，传播就此停止。每次变化，每条 link 每个方向最多一帧。
  • 补齐：每次 link 建立，双方先报 known（每台机器的 seq），再补发对方缺的。断开期间漏掉的都在这一步补上。
  • 自己的旧记录：daemon 重启后表是空的，新 seq 取当前时间。如果时钟倒退过，邻居手里的旧记录 seq 更大，会在补齐时传回来；本机发现后，用更大的 seq 重新发布盖过它。
  • 每台机器各算各的视图：机器列表、谁可达、最短路径，都由本机根据手里的记录计算。一条 link 只有在两端的记录都列出对方时才算数（对端没有记录时以发起方为准），所以一端已经断了、另一端的旧记录还列着，这条边也不算。

记录里还捎带了两样全网共识：subnet（每台机器在 net.since 里写着它认为的 subnet 是什么时候选的，大家都取最大的）和 gst IP（每台机器自己选，冲突时 id 小的保留）。见场景 7。

每类状态的一致性

状态谁写怎么传冲突时保证没有保证的
机器的记录
名字、links、net		那台机器自己洪泛 + 建 link 时补齐seq 大的胜连通分量内最终一致30 分钟没刷新就过期删除；不写盘；最多 1024 条，超出静默丢弃
成员身份没有单独的状态等于"有一条没过期的记录"—无离线 30 分钟即被所有机器忘掉；重启即忘掉所有别人
网络的 subnet任意机器（gst subnet，或第一次自动选）记录的 netsince 大的胜，相同时按字符串最终一致since 是墙钟，时钟快的机器手动选的会赢；传播期间不同 subnet 的机器互相解析不到、包不通
gst IP每台机器自己记录的 net.address重复时 id 小的保留，大的重新选最终无冲突只看自己当时的视图；分区两边可能选到同一个地址，合并后才发现并改掉
机器名那台机器自己记录不处理，名字可以重复—重名时按名字解析失败（DNS 返回 NXDOMAIN），只能用 id
link 的配置发起方不传；只在发起方的配置文件里——别的机器只能在 node.status 里看到；只能在发起方删

05

已知的缺口

都是当前代码的实际行为，按影响排列。

离线 30 分钟 = 被移出网络记录只靠 SSH link 续期。一台机器休眠或断网超过 30 分钟，所有机器删掉它的记录：DNS 不再解析它，WireGuard 去掉它，它的地址也不再算作已占用。它自己那边同样删掉所有别人。重连后要等同步完成才恢复，这段时间里 .gst 查询得到 NXDOMAIN（不带 SOA），可能被系统缓存。
重启即失忆记录只在内存里。daemon 重启后，在第一条 link 连上并补齐之前，本机不知道任何别的机器。
恢复慢：link 退避不因换网络重置link 失败后的等待最长 5 分钟。UDP 路径在换网络时会清掉退避立刻重试，link 不会：唤醒后可能要等上一轮退避结束才重连。
视图不一致时调用会失败，不会换路发起方按自己的视图算路径。沿途某条 link 刚断、而发起方还没收到更新时，relay.open 在那一跳返回错误。net.packets 1 秒后重开，direct.offer 退避后重试，其余调用直接报错。
link.remove 是尽力而为3 秒没送到就放弃。对端没听到时，它到那些已经无路可达的机器的 UDP 路径，要等对方记录过期才关闭。
两处依赖墙钟seq 取当前纳秒（有"见过的最大值"兜底，时钟倒退能恢复）；subnet 的 since 也取墙钟，没有兜底，时钟快的机器选的 subnet 会胜过之后别人选的。
分区期间各自演化两半各自改名、改 subnet、选地址。重新连上后按 seq、since、id 收敛；如果分开超过 30 分钟，两边已互相忘记，重连等同于两个网络第一次合并。
没有签名，成员之间完全信任记录和调用都不签名，任何一台成员机器都可以伪造别人的记录、冒用别人的 id。身份只靠 SSH 授权。
上限静默生效每台机器最多 1024 条记录，每条最多 1024 条 link，单条记录不能超过半帧（512 KiB）；超出的直接丢弃，不报错。
